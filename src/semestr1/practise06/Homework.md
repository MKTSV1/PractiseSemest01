### Рівень 1: Базовий (2 бали)
#### 📝 Завдання 1: Годинник із нормалізацією часу

- **Клас для виконання:** `Task1TimeClock` (файл `Task1TimeClock.java`)
- **Допоміжний клас:** `Time` (файл `Time.java`)
- **Рекомендований пакет:** `semester1.practice06.homework`
- **Бали за завдання:** **2 бали**

**Контекст:** Потрібен клас «час доби», який вміє зберігати години, хвилини й секунди, «перескакувати» через північ і гарно друкувати себе.

**Клас `Time`:**
| Елемент | Вимога |
|:---|:---|
| Поля | `private int hours`, `private int minutes`, `private int seconds` |
| Конструктор `Time(int totalSeconds)` | Приймає кількість секунд від початку доби. Якщо значення більше за добу (86400 с), «обертає» його: `totalSeconds % 86400` |
| Конструктор `Time(int hours, int minutes, int seconds)` | **Обов'язково викликає перший конструктор через `this(...)`**, а не дублює код |
| `int toSeconds()` | Повертає час у секундах від початку доби |
| `void addSeconds(int extra)` | Додає секунди до цього об'єкта (час переходить через північ: `23:59:50 + 20 с = 00:00:10`). `extra ≥ 0` |
| `boolean isBefore(Time other)` | `true`, якщо цей час раніший за `other` |
| `String toString()` | Формат `HH:MM:SS` **з ведучими нулями** |

> [!WARNING]
> **Обмеження:** не використовуйте `String.format()` та `printf` для ведучих нулів. Напишіть для цього власний допоміжний `private`-метод із тернарним оператором.
> Дублювання логіки розбиття секунд на години/хвилини/секунди у двох місцях вважається поганим стилем — винесіть її в один `private`-метод.

**Що необхідно зробити в `main`:**
1. Створити `start = new Time(8, 59, 30)`, `lunch = new Time(45300)`, `night = new Time(23, 59, 50)` і вивести їх.
2. Додати до `start` 45 секунд, до `night` — 20 секунд; вивести результати.
3. Вивести результати `start.isBefore(lunch)`, `lunch.isBefore(start)` та `night.isBefore(lunch)` (зверніть увагу, що `night` уже змінився!).
4. Створити `new Time(0, 0, 90061)` і вивести, у що перетворився час.

**Очікуваний результат у консолі:**
```text
Старт:  08:59:30
Обід:   12:35:00
Ніч:    23:59:50
-----------------------------
Старт + 45 сек:   09:00:15
Ніч + 20 сек:     00:00:10
-----------------------------
Старт раніше за обід? true
Обід раніше за старт? false
Ніч раніше за обід?   true
90061 секунд -> 01:01:01 (наступна доба)
```

**Контекст:** Реалізуйте власний тип «звичайний дріб», який завжди зберігається у **скороченому** вигляді та вміє виконувати арифметику, повертаючи **нові об'єкти**.

**Клас `Fraction`:**
| Елемент | Вимога |
|:---|:---|
| Поля | `private int numerator`, `private int denominator` |
| Конструктор `Fraction(int numerator, int denominator)` | 1) якщо знаменник `0` — вивести `Помилка: знаменник не може бути 0, встановлено 1` і взяти `1`; 2) якщо знаменник від'ємний — перенести мінус у чисельник; 3) **скоротити** дріб за допомогою найбільшого спільного дільника (алгоритм Евкліда в циклі `while`) |

| `Fraction multiply(Fraction other)` | Добуток |
| `Fraction divide(Fraction other)` | Ділення. Якщо `other` дорівнює нулю — вивести `Помилка: ділення на нуль, повернуто 0/1` і повернути `0/1` |

| `boolean isEqualTo(Fraction other)` | Рівність двох дробів |
| `String toString()` | Формат `чисельник/знаменник`; якщо знаменник дорівнює 1 — тільки чисельник (`2`, а не `2/1`) |

> **Увага:** додавання, віднімання тощо мають працювати для будь-яких коректних дробів, а не лише для прикладів з `main`. Готові числа в `println` («захардкоджений» результат) вважаються порушенням.

**Що необхідно зробити в `main`:** створити дроби `a = 1/2`, `b = 3/4`, `c = 6/-8`, `d = 10/5`, `e = 5/0`, виконати арифметику та порівняння, а наприкінці створити `zero = 0/7` і поділити `a` на нього.

**Очікуваний результат у консолі:**
```text
Помилка: знаменник не може бути 0, встановлено 1
a = 1/2
b = 3/4
c = -3/4   (було 6/-8)
d = 2     (було 10/5)
e = 5     (було 5/0)
----------------------------------
a + b = 5/4
a - b = -1/4
a * b = 3/8
a / b = 2/3
b + c = 0
----------------------------------
a як double: 0.5
b як double: 0.75
a > b ? false
b > a ? true
a рівне 2/4 ? true
----------------------------------
zero = 0
Помилка: ділення на нуль, повернуто 0/1
a / zero = 0
```
*(Перший рядок помилки з'являється **на самому початку** — бо конструктор `e = new Fraction(5, 0)` виконується ще до виведення. Те саме з другою помилкою: метод `divide` друкує її до того, як `println` виведе рядок `a / zero = ...`.)*

### Рівень 3: Підвищений (4 бали)
#### 📝 Завдання 3: Банківські рахунки, комісія та добовий ліміт

- **Клас для виконання:** `Task3BankTransfer` (файл `Task3BankTransfer.java`)
- **Допоміжний клас:** `Account` (файл `Account.java`)
- **Рекомендований пакет:** `semester1.practice06.homework`
- **Бали за завдання:** **4 бали**

**Контекст:** Модуль інтернет-банкінгу. Кожен рахунок — окремий об'єкт. Переказ відбувається між **двома об'єктами**, тому метод `transfer` приймає як параметр інший `Account`.

**Клас `Account`:**
| Елемент | Вимога |
|:---|:---|
| Поля | `private String owner`, `private double balance`, `private double spentToday` (скільки вже витрачено за сьогодні), `private final double DAILY_LIMIT = 5000.0` |
| Конструктор `Account(String owner, double balance)` | Ініціалізує власника та стартовий баланс |
| `boolean deposit(double amount)` | Поповнення. `false`, якщо `amount <= 0`. Поповнення **не** впливає на добовий ліміт |
| `boolean withdraw(double amount)` | Зняття. Успішне тільки якщо одночасно: `amount > 0`, `amount <= balance` та `spentToday + amount <= DAILY_LIMIT` (ліміт **включно**). У разі успіху збільшує `spentToday` |
| `boolean transfer(Account target, double amount)` | Переказ. **Комісія:** якщо `amount > 1000` — 1% від суми, інакше 0. З рахунку відправника знімається `amount + commission` (через метод `withdraw`, тому діють усі його перевірки та добовий ліміт), на рахунок отримувача зараховується **`amount` без комісії**. Переказ неможливий (`false`), якщо `target == null` або `target == this` |
| `String toString()` | Формат: `Рахунок [Олена]: 4480.0 грн (витрачено сьогодні: 2520.0 з 5000.0)` |

> [!IMPORTANT]
> **Ключові вимоги:**
> - Ніяких дублювань перевірок: `transfer` повинен **використовувати** `withdraw` та `deposit`.
> - Перевірку `target == null` робіть **першою**, інакше отримаєте `NullPointerException`.
> - Комісію розраховуйте **тернарним оператором**.
> - Для перевірки на «той самий рахунок» використовуйте порівняння посилань `target == this`.

**Що необхідно зробити в `main`:** створити `olena` (баланс 6000) і `taras` (баланс 500), вивести початковий стан, виконати 8 операцій зі сценарію нижче (вивести результат кожної), вивести підсумок.

**Очікуваний результат у консолі:**
```text
=== СТАРТ ===
Рахунок [Олена]: 6000.0 грн (витрачено сьогодні: 0.0 з 5000.0)
Рахунок [Тарас]: 500.0 грн (витрачено сьогодні: 0.0 з 5000.0)

1. Олена поповнює рахунок на 1000: true
2. Олена -> Тарас, 2000:           true
3. Олена -> Тарас, 3500:           false
4. Тарас знімає 3000:              false
5. Тарас знімає -5:                false
6. Олена -> Олена, 100:            false
7. Олена -> null, 100:             false
8. Олена -> Тарас, 500:            true

=== ПІДСУМОК ===
Рахунок [Олена]: 4480.0 грн (витрачено сьогодні: 2520.0 з 5000.0)
Рахунок [Тарас]: 3000.0 грн (витрачено сьогодні: 0.0 з 5000.0)
```

### 2. Формула підсумкової оцінки

$$\text{Підсумкова оцінка} = \min\left(5,\; \sum \text{Бали за виконані завдання} - \text{Штрафи}\right)$$

> [!TIP]
> **Приклади підрахунку:**
> - Тільки **Завдання 1** без помилок: $\mathbf{2\ бали}$.
> - **Завдання 1 (2) + Завдання 2 (3)**: $2 + 3 = \mathbf{5\ балів}$.
> - **Завдання 3 (4)** зі штрафом −1 за незахищене `null`: $4 - 1 = \mathbf{3\ бали}$.
