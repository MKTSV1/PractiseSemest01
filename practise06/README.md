## 📚 1. Теоретичні відомості

### 1.1. Навіщо потрібне ООП?
Уявіть, що потрібно зберігати дані про трьох студентів. Зі знань попередніх практичних ви напишете щось таке:
```java
String student1Name = "Олена";  int student1Age = 18;  double student1Grade = 90.5;
String student2Name = "Тарас";  int student2Age = 19;  double student2Grade = 78.0;
String student3Name = "Ірина";  int student3Age = 18;  double student3Grade = 85.5;
```
А тепер уявіть **300 студентів** і необхідність передати «одного студента» у метод. Дані розкидані по десятках окремих змінних і ніяк не пов'язані між собою — легко помилитися й заплутатися.

**ООП вирішує цю проблему:** ми описуємо «студента» **один раз** як окремий тип даних, який збирає всі його властивості разом і вміє щось робити (представитися, порахувати середній бал тощо).

---

### 1.2. Клас і об'єкт
| Поняття | Аналогія | Що це в Java |
| :--- | :--- | :--- |
| **Клас** | Креслення будинку / форма для печива | Опис: які в об'єктів будуть **поля** (дані) та **методи** (дії). Існує один раз у коді. |
| **Об'єкт** | Конкретний збудований будинок / печиво | Екземпляр класу, створений командою `new`. Має **свої власні** значення полів. Їх може бути скільки завгодно. |

За одним класом можна створити багато об'єктів, і кожен буде незалежним від інших.

---

### 1.3. Опис класу: поля та методи
```java
package semester1.practice06.block1;

public class Student {
    // ПОЛЯ (стан об'єкта)
    String name;
    int age;
    double averageGrade;

    // МЕТОД (поведінка об'єкта)
    void introduce() {
        System.out.println("Привіт! Я " + name + ", мені " + age + " років.");
    }
}
```
- **Поля** — це змінні, оголошені **всередині класу, але поза методами**. Вони належать кожному окремому об'єкту.
- **Методи** — дії об'єкта. Усередині методу поля свого об'єкта доступні просто за іменем (`name`, `age`).
- Зверніть увагу: тут **немає** слова `static` у методі `introduce()` — це метод **об'єкта**, а не класу.

---

### 1.4. Створення об'єктів та доступ до членів класу
Новий об'єкт створюється оператором `new`. Доступ до поля чи методу — через крапку:
```java
public class Block1Demo {
    public static void main(String[] args) {
        Student first = new Student();     // створили перший об'єкт
        first.name = "Олена";              // записали значення в поля
        first.age = 18;
        first.averageGrade = 90.5;

        Student second = new Student();    // створили другий, незалежний об'єкт
        second.name = "Тарас";
        second.age = 19;
        second.averageGrade = 78.0;

        first.introduce();                 // виклик методу об'єкта first
        second.introduce();                // виклик методу об'єкта second
    }
}
```
*Вивід у консолі:*
```text
Привіт! Я Олена, мені 18 років.
Привіт! Я Тарас, мені 19 років.
```
Той самий метод `introduce()` видав **різні результати**, бо працює з даними того об'єкта, на якому його викликали.

**Розбір рядка `Student first = new Student();`:**
1. `Student first` — оголошуємо змінну типу `Student` (поки що це лише «пульт», який ні на що не вказує).
2. `new Student()` — у пам'яті створюється новий об'єкт.
3. `=` — «пульт» `first` прив'язується до створеного об'єкта.

### 1.5. Значення полів за замовчуванням
Поля, яким ми **нічого не присвоїли**, отримують значення автоматично:

| Тип поля | Значення за замовчуванням |
| :--- | :--- |
| `byte`, `short`, `int`, `long` | `0` |
| `float`, `double` | `0.0` |
| `boolean` | `false` |
| `char` | `'\u0000'` (службовий нульовий символ) |
| `String` та будь-який клас | `null` («посилання нікуди не вказує») |

```java
class DefaultsDemo {
    int number;
    double price;
    boolean ready;
    String title;
}
// ...
DefaultsDemo d = new DefaultsDemo();
System.out.println(d.number + " | " + d.price + " | " + d.ready + " | " + d.title);
```
*Вивід:* `0 | 0.0 | false | null`

> [!WARNING]
> Це правило діє **тільки для полів**. **Локальні змінні** (оголошені всередині методу) значень за замовчуванням **не мають**:
> ```java
> int x;
> System.out.println(x); // ПОМИЛКА КОМПІЛЯЦІЇ: variable x might not have been initialized
> ```

---

### 1.6. Методи об'єкта: параметри та повернення значення
Методи класу пишуться за тими самими правилами, що й звичайні методи: тип результату (`void`, `int`, `double`, `boolean`, `String` ...), назва, параметри.
```java
class Counter {
    int value;                       // поле: поточне значення

    void increment() {               // нічого не повертає, змінює поле
        value++;
    }

    void add(int amount) {           // приймає параметр
        value += amount;
    }

    int getValue() {                 // повертає значення
        return value;
    }
}
// ...
Counter a = new Counter();
a.increment();
a.increment();
a.add(10);
Counter b = new Counter();           // зовсім окремий лічильник
System.out.println(a.getValue() + " " + b.getValue());   // 12 0
```
> [!TIP]
> Метод може викликати інші методи свого ж класу просто за назвою: `printInfo()` може всередині викликати `area()` та `perimeter()`.

### 1.7. Конструктори
Писати `first.name = ...; first.age = ...;` після кожного `new` — довго, і є ризик забути заповнити якесь поле. **Конструктор** — це спеціальний «метод», який автоматично виконується в момент створення об'єкта й задає початковий стан.

**Правила конструктора:**
1. Назва **точно збігається** з назвою класу.
2. **Немає типу результату** (навіть `void`).
3. Викликається тільки через `new`.

```java
class Book {
    String title;
    String author;
    int pages;

    Book(String title, String author, int pages) {   // конструктор
        this.title = title;
        this.author = author;
        this.pages = pages;
    }
}
// ...
Book book = new Book("Кобзар", "Тарас Шевченко", 320);
```

#### Конструктор за замовчуванням
Якщо ви **не написали жодного** конструктора, компілятор непомітно додає порожній: `Book() { }`. Саме тому `new Student()` у п. 1.4 працював без жодного конструктора в класі.

> [!CAUTION]
> Як тільки ви напишете **хоча б один власний** конструктор, автоматичний **зникає**! Тоді `new Book()` без аргументів дасть помилку компіляції — доки ви не додасте порожній конструктор вручну.

#### Перевантаження конструкторів
Класу можна дати **кілька конструкторів** з різними наборами параметрів. Java вибере потрібний за кількістю та типами аргументів у `new`:
```java
class Rectangle {
    double width;
    double height;

    Rectangle(double width, double height) {   // прямокутник
        this.width = width;
        this.height = height;
    }

    Rectangle(double side) {                   // квадрат
        this(side, side);
    }

    Rectangle() {                              // одиничний квадрат
        this(1, 1);
    }

    double area() {
        return width * height;
    }
}
// ...
Rectangle r1 = new Rectangle(4, 5);   // 20.0
Rectangle r2 = new Rectangle(3);      // 9.0
Rectangle r3 = new Rectangle();       // 1.0
```

### 1.8. Ключове слово `this`
`this` — це «**я сам**»: посилання на поточний об'єкт, усередині якого виконується код.

**1) Розрізнення поля та параметра з однаковою назвою (shadowing):**
```java
Book(String title, String author, int pages) {
    this.title = title;   // зліва — ПОЛЕ об'єкта, справа — ПАРАМЕТР конструктора
}
```
Якщо написати без `this`, тобто `title = title;`, параметр присвоїться сам собі, а поле залишиться зі значенням за замовчуванням (`null`)! IntelliJ підкреслить такий рядок попередженням «Assignment to itself».

**2) Виклик іншого конструктора: `this(...)`**
Використовується, щоб не дублювати код (див. приклад із `Rectangle`). Правило: `this(...)` має бути **першою інструкцією** в конструкторі.

### 1.9. Посилальні типи: що насправді лежить у змінній
Змінна примітивного типу (`int x = 5;`) зберігає **саме значення**. Змінна класового типу (`Student s`) зберігає **посилання** (адресу) на об'єкт, який живе в іншій області пам'яті — **купі (heap)**.

```java
Student a = new Student();
a.name = "Олена";
Student b = a;          // копіюється ПОСИЛАННЯ, а не об'єкт!
b.name = "Тарас";
System.out.println(a.name);   // Тарас  (!)
```
```text
 Змінні (stack)                 Об'єкти (heap)
┌─────────────┐              ┌──────────────────────┐
│ a ──────────┼─────┐        │ Student              │
│ b ──────────┼─────┴──────► │   name = "Тарас"     │
└─────────────┘              │   age  = 0           │
                             └──────────────────────┘
```
Обидві змінні вказують на **один і той самий** об'єкт, тому зміна через `b` видна і через `a`.

#### `==` порівнює посилання, а не вміст
```java
Student s1 = new Student();
Student s2 = new Student();
Student s3 = s1;
System.out.println(s1 == s2);   // false: це два різних об'єкти (навіть якщо поля однакові)
System.out.println(s1 == s3);   // true:  це один об'єкт, на який вказують дві змінні
```
Для **рядків** (`String`) порівнювати за вмістом треба методом `.equals()` — ви вже знаєте це з практичної №3.

#### `null` та `NullPointerException`
`null` означає «посилання нікуди не вказує». Звертатися через таке посилання до полів чи методів **не можна** — програма аварійно завершиться:
```java
Student nobody = null;
System.out.println(nobody == null);    // true — перевіряти на null можна і потрібно
System.out.println(nobody.name);       // NullPointerException!
```
> [!IMPORTANT]
> `NullPointerException` (NPE) — найпоширеніша помилка у Java. Захист простий: коли змінна **може** бути `null`, спершу перевіряйте `if (obj != null)`.

### 1.10. Передача аргументів у методи
Java завжди передає аргументи **за значенням** — тобто копіює те, що лежить у змінній:
- **Примітиви:** копіюється саме число → метод працює зі своєю копією, оригінал не змінюється.
- **Об'єкти:** копіюється **посилання** → метод бачить **той самий об'єкт**, тому може змінити його поля.

```java
static void tryIncrease(int x) { x++; }                          // змінює лише копію
static void birthday(Person p) { p.setAge(p.getAge() + 1); }     // змінює справжній об'єкт

int x = 5;
tryIncrease(x);
System.out.println(x);                 // 5  (не змінилося)

Person p = new Person("Іра", 20);
birthday(p);
System.out.println(p.getAge());        // 21 (змінилося)
```
> [!NOTE]
> Слово `static` у цих допоміжних методах поки що сприймайте як «спосіб викликати метод прямо з `main`, не створюючи об'єкт». Детально про нього — пізніше.

### 1.11. Метод `toString()`
Якщо вивести об'єкт через `System.out.println(book)`, Java за замовчуванням надрукує щось незрозуміле на кшталт `Book@1b6d3586` (назва класу й «хеш-код»). Щоб отримати гарний текст, **перевизначте** метод `toString()` — Java викличе його автоматично при виводі та при конкатенації зі `String`:
```java
class Book {
    String title;
    String author;
    int pages;

    // ... конструктор ...

    @Override
    public String toString() {
        return "«" + title + "», " + author + ", " + pages + " стор.";
    }
}
// ...
System.out.println(book);                  // «Кобзар», Тарас Шевченко, 320 стор.
System.out.println("Моя книга: " + book);  // Моя книга: «Кобзар», Тарас Шевченко, 320 стор.
```
- Анотація `@Override` обов'язкова за стилем: вона дозволяє компілятору перевірити, що ви справді перевизначаєте метод, а не зробили помилку в назві.
- Сигнатура строго така: `public String toString()`.

### 1.12. Вступ до інкапсуляції: `private`, геттери та сеттери
Поки що будь-який код може написати `student.age = -500;`, і об'єкт опиниться в безглуздому стані. **Інкапсуляція** — це «захисна оболонка»: поля ховають, а доступ дають через методи, які перевіряють дані.

- `private` — поле видно **тільки всередині свого класу**.
- `public` — видно звідусіль.
- **Геттер** (`getAge()`) — читає значення поля.
- **Сеттер** (`setAge(int age)`) — змінює значення, попередньо **перевіривши** його.
- Для `boolean`-полів геттер зазвичай називають `isXxx()` (наприклад, `isAvailable()`).

```java
class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        setAge(age);                       // повторно використовуємо перевірку
    }

    public String getName() { return name; }
    public int getAge()     { return age; }

    public void setAge(int age) {
        if (age >= 0 && age <= 150) {
            this.age = age;
        } else {
            System.out.println("Некоректний вік: " + age);
        }
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }
}
// ...
Person p = new Person("Іра", 20);
p.setAge(-4);                // Некоректний вік: -4
p.setAge(200);               // Некоректний вік: 200
// p.age = 500;              // ПОМИЛКА КОМПІЛЯЦІЇ: age has private access in Person
System.out.println(p);       // Person{name='Іра', age=20}
```

> [!TIP]
> **Допомога від IntelliJ IDEA:** комбінація **Alt + Insert** (Windows/Linux) або **Cmd + N** (macOS) всередині класу відкриває меню **Generate**, де можна згенерувати **Constructor**, **Getter and Setter** та **toString()**.
> Але спершу напишіть кілька конструкторів і геттерів **руками** — так ви зрозумієте, що саме генерує середовище.

## 📋 3. Критерії оцінювання та чек-лист для самоперевірки

### Чек-лист перед здачею:
1. **Код компілюється** без червоних підкреслень у IntelliJ IDEA.
2. **Один клас — один файл**, назва файлу збігається з назвою класу; клас-запускач лише створює об'єкти й викликає методи.
3. **Іменування:** класи — `PascalCase` (`CBankAccount03`), поля/методи/змінні — `camelCase` (`averageGrade`), пакети — `lowercase` (`semester1.practice06.block1`).
4. **`this`:** у конструкторах і сеттерах поля та параметри з однаковими іменами розрізняються через `this.`
5. **Блок 5:** усі поля приватні (`private`); дані проходять перевірку в сеттерах/конструкторах; для змін об'єкта є методи, а не прямий доступ до полів.
6. **Рядки порівнюються через `.equals()`**, посилання на об'єкти — через `==` лише тоді, коли справді треба перевірити «один і той самий об'єкт».
7. **Захист від `null`:** перед викликом методу/поля через змінну, яка може бути `null`, є перевірка `!= null`.
8. **`toString()`** має `@Override` та правильну сигнатуру `public String toString()`.
9. **Форматування:** код відформатовано (`Ctrl + Alt + L` у Windows/Linux, `Cmd + Option + L` у macOS).

### Типові помилки початківців
| Помилка | Симптом | Як виправити |
| :--- | :--- | :--- |
| Забули `this.` у конструкторі | Поля залишаються `null`/`0` | Писати `this.name = name;` |
| Додали конструктор з параметрами й викликаєте `new Клас()` | `constructor ... cannot be applied to given types` | Додати конструктор без параметрів |
| Звернення до поля через `null` | `NullPointerException` | Перевіряти `if (obj != null)` |
| Порівняння об'єктів через `==` | `false` для однакових за змістом об'єктів | Порівнювати поля або писати `equals` (пізніше) |
| Спроба змінити `private`-поле ззовні | `has private access in ...` | Використовувати геттер/сеттер |
| Забули створити елементи масиву об'єктів | `NullPointerException` при `group[i].getName()` | `group[i] = new Student(...)` |
| `toString()` без `public` або з помилкою в назві | У консолі `Клас@1b6d3586` | Додати `@Override`, перевірити сигнатуру |
